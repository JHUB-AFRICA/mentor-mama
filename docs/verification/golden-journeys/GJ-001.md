# Mentor offline session reconciliation

## Preconditions

- A local mentor account with one active placement and a current mentor
  assignment.
- The browser begins with no session queue entries for that account.
- The API and portal run locally; the session POST may be intercepted only by
  the browser test.

## Steps

1. The mentor opens the active placement and enters a valid session.
2. The browser interrupts the session POST to simulate a signal loss.
3. The mentor returns to the workspace and sees the session under **Saved on
   this device**.
4. The browser restores the local API connection and the mentor chooses **Sync
   now**.
5. The client reads the command status, safely posts only if it was not
   committed, and removes the queue item after confirmation.
6. In the rejection branch, the placement is paused or the mentor is
   reassigned before sync. The queued session moves to **Needs attention** and
   remains visible until the mentor retries or deliberately discards it.

## Expected states

- The original idempotency UUID is retained for every retry.
- A successful or lost-response command produces exactly one server session.
- A non-retryable late rejection is never discarded silently or accepted
  against a paused, closed, or reassigned placement.
- Queue entries are visible only to their originating account.
